# Field report 01 — ChopChop (LiveTracking + FlightDeck screens)

The first real use of the suite, on a project with nothing in common with the one it was built
from. This is the record; the working artifacts went straight to
`evals/generating-powerapps-yaml/fixtures/` because they were good enough to become regression
fixtures, which is a better home than this folder.

**Read this one if you are filing your first report.** It is what a useful record looks like. Note
what it does *not* do: it does not soften `present_and_ignored`, and it does not stop at the
structured fields. The single most valuable thing in it is `biggest_miss`, which is free text.

The original round-3 record used the schema from `prompts/followup-record-only.md`. It is
normalised here into the canonical schema so `triage_feedback.py` reads it. Nothing was reworded —
the verbatim strings, the `rule_status` verdicts and `biggest_miss` are exactly as filed. The full
three-round analysis is in [`ledger/09-field-report-01-chopchop.md`](../../ledger/09-field-report-01-chopchop.md).

```yaml
  The validator passes files that will render wrong, and the skill never says so. Every rule in
  SKILL.md is about whether the paste parses; nothing addresses whether the screen looks right
  afterwards. So I ran the validator, got "Clean. Safe to paste into Power Apps Studio.", and
  believed it — three times. A one-line warning on page one ("a clean validator run means it will
  paste, not that it will render; geometry, Template* scope, borders and container heights are

  rounds into one.
```

## What was done about it

All of it, in `generating-powerapps-yaml` v1.1.0 → v1.3.0. See `dist/CHANGELOG.md`.

The headline: **`Clean. Safe to paste into Power Apps Studio.` was the suite's own sentence and it
was an overclaim.** It now reads `No errors found. This should PARSE and paste.`, always followed
by an explicit `NOT CHECKED` block. Both verbatim Studio errors became checks. `SpaceBetween` was
promoted to the confirmed enum set, and the eleven warnings it used to raise are gone.

One v1.2.0 rule was walked *back* on the strength of `v3_pasted_into_studio: no` — the divider
container is marked not-yet-paste-tested rather than asserted.
